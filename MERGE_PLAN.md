## 0. Ключевые выводы

1. **По ТЗ каждый блок = одно устройство** (блок 1 — планшет, блоки 2–4 — тач 43″), на котором лежат интерактивы обоих треков. Значит, нужен один бандл с меню блока, а не два приложения рядом.
2. **Ориентации совпадают** между проектами по блокам — это удача, ничего переворачивать не надо:
   - Блок 1 (менеджмент): Fire `management`/`calendars` — portrait; Informatika `/` (доступность) — portrait.
   - Блок 2 (креатив): Fire `creative` — portrait; Informatika `/creative-director` — portrait.
   - Блок 3 (аналитика): Fire `data` — landscape; Informatika `/ml-dev` — landscape (есть и `-vert`).
   - Блок 4 (разработка): Fire `development` — landscape; Informatika `/ai-trener` — landscape.
3. **Рекомендация — база `YandexFireInMyHall`, интерактивы из Informatika портируются в него.** Причины: там дизайн-система, типизированные данные, 30 готовых игровых механик (половина нужных уже есть: `distribute`, `match`, `categorize`, `quiz`, `Videos`), гайды для агентов. Informatika — 8 нужных экранов по 150–350 строк JSX, портировать дешевле, чем тащить два стека и две дизайн-системы на одну выставку. Обратный вариант (всё в Next) потребовал бы переписать 20+ игр.
4. **Статус контента Informatika хуже, чем кажется:** у 2 из 12 интерактивов (альт-текст, симулятор зрения) физически нет ассетов, «ИИшные стихи» — 4 пары из 10 по доку, «Собери робота» — фейковые картинки вместо генерации, 3 видео «Познакомься с …» вообще не в приложении (играли на внешнем медиасервере зала через `/manage` → `192.168.3.2:9980`).
5. **Видео, которых нет ни в одном проекте:** «Познакомься с креативным директором», «Познакомься с ML-инженером» (в Fire в `data.ts` есть запись `ml-engineer.mp4`, файла нет), «Познакомься со специалистом по цифровой доступности». Три ролика — запросить у заказчика (§4).
6. В `yandex-informatika` в репозитории лежат секреты: fal.ai-ключ (`pages/api/generate-robot.js:4-7`), mailgun (`mailgun-configuration.js:15`), prismic (`prismic-configuration.js:3-4`). При переносе — не копировать, ключи отозвать.

## 3. Как мерджим: шаги

### 3.1 Каркас
1. В F заменить dev-заглушку `HomePage` на **4 меню блоков**: `/block/management`, `/block/creative`, `/block/data`, `/block/development` (или оставить киоскам стартовые URL прямо на разделы — но тогда нет входа в интерактивы «Информатики»). В меню блока — два раздела: «Профориентация» (существующие `Menu` разделов F) и «Информатика во всём» (новые задания). Стартовый URL киоска = меню блока.
2. Кнопка «назад» из меню раздела в меню блока: сейчас `*Menu.tsx` не передают `onBack` — добавить.
3. Общий `Layout` блока берёт `theme`/`orientation` из данных, а не из литералов (сейчас 4 папки разделов — копипаста с разными литералами `theme="orange"`; см. `creative/Description.tsx:11`).

### 3.2 Масштабирование под реальные экраны
F жёстко 1920×1080 / 1080×1920 (`Background.module.css:8-16`), игры считают от этих констант (`PlaylistAnatomyGame.tsx:93`, `SwipeGame.tsx:121` и др.). Для планшета (блок 1) и на случай 4K-панелей — добавить обёртку `transform: scale(min(vw/1080, vh/1920))` над `Background`. Это дешевле, чем rem-подход I, и не ломает игры, считающие в px.

### 3.3 Перенос интерактивов I → F
Порядок по риску (сначала те, где нет блокеров по контенту):
1. **Агат-7** → `distribute` в `creative/data.ts` (только данные + картинки). ~0.5 дня.
2. **Слоганы** → `match` с 3 шагами. ~0.5 дня.
3. **ИИшные стихи** → `quiz` в `development/data.ts`, 10 пар. ~0.5 дня.
4. **Тифлокомментарий** → страница с 3 кнопками + fullscreen `<video>`. ~0.5 дня. Видео перенести в `public/videos/access/`.
5. **Data Set** → новая `count`. ~1 день. Перенести `raw_images`/`segmented_images` в `public/assets/games/access/dataset/`.
6. **История рекламы** → новая `timeline`. ~1 день.
7. **Глазами другого** → новая `compare` на CSS-фильтрах. ~0.5 дня + одна хорошая фотография.
8. **Альт-текст** → `match` + аудио. ~1 день, **блокер: 3 картинки + 3 аудио + 3 реальных описания**.
9. **Собери робота** → новая `builder`. ~1 день без генерации / +1 день с fal.ai через отдельный микро-бэкенд (F — статика на nginx, API-роута нет).

Все тексты — в `data.ts` соответствующего раздела; исходники I остаются в `Games/00X/` как md для истории (по `GAME_SPEC.md` — завести `Games/005-access/` и т.п.).

### 3.4 Что НЕ переносим из I
- `constants/texts.js`, `project.js`, `offer.js`, `utils/store.js`, `useGeneration`, prismic/mailgun/emailjs/three/locomotive — наследие шаблона Snapyfit, музеем не используется.
- `/manage` (пульт LAN-контроллера залов `192.168.3.2:9980`) — относится к другой площадке; если на фестивале будет такой же контроллер — отдельная задача.
- `/data-journalist`, `/ai-trener` Flow 1/2/4, `CreativeDirector` Flow 1 — не в ТЗ.
- 12-минутный idle-сброс — в ТЗ F явно «во время бездействия — главное меню» (`Games/001/Основа.md:3`); идею возврата в меню блока по таймауту стоит обсудить, но это новая фича.

### 3.5 Деплой
F: Dockerfile → nginx static, образ ~0.6 ГБ из-за видео (498 МБ + 69 МБ от I + 3 новых ролика). Варианты: оставить как есть (киоски офлайн, всё в образе — надёжно) или вынести видео в volume. `nginx.conf:14-18` кэширует `/assets/` immutable на год — при замене картинок под тем же именем киоск покажет старые; либо версионировать имена, либо убрать immutable для `/assets/games/`.
